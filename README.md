# Лифт — приложение для пилотов

У каждого пилота свой кабинет: стратегия развития бизнеса, задачи с дедлайнами, анкета для сайта,
ссылки на его сайт, ботов и другие инструменты. Игра: за задачи в срок и анкету — баллы, баллы поднимают на этажи.
Команда ведёт пилотов в панели `/team`.

- Веб-приложение: React (apps/web), сервер: Express + SQLite (apps/api).
- APK для Android/RuStore: Capacitor (apps/web/android). APK открывает приложение с сервера, поэтому
  обновления экранов доходят до пилотов без перевыпуска в RuStore.

## Как это работает

1. Команда входит в `https://<домен>/team` по паролю (`TEAM_PASSWORD` в `.env`).
2. «Пригласить пилота» → приложение выдаёт ссылку-приглашение → отправляем её пилоту.
3. Пилот открывает ссылку (в браузере или в установленном APK), даёт согласие на обработку ПДн и попадает в кабинет.
   Ссылка многоразовая (телефон + компьютер). «Новая ссылка» в карточке пилота закрывает старые входы.
4. В карточке пилота: профиль и цель, этапы стратегии, задачи (срок, баллы), инструменты, ответы анкеты.

### Баллы и этажи
- Задача отмечена до конца дня срока (по Москве) или без срока — все баллы, позже — половина.
- Обязательные вопросы анкеты заполнены — 200 баллов.
- Этажи: 0, 150, 400, 750, 1200, 1800, 2500, 3300, 4200, 5200, 6500, 8000 баллов (`apps/api/src/game.ts`).
- Серия — недели подряд без просрочек.

### Анкета
46 вопросов из прежней Google Формы — `apps/api/src/survey.ts`. Ответы хранятся по id вопроса (`q1`…`q46`):
не менять id существующих вопросов, новым давать новые. Ответы сохраняются сами, файлы (фото, логотип, прайс)
загружаются прямо в анкете и доступны по случайной ссылке `/files/<id>`.

## Сервер

Отдельная папка и служба, соседей («Цех №4», конструктор магазинов) не трогает.

```bash
cd /home/mac-user/my-projects
git clone git@github-lift:evgensof1990/lift-app.git lift-app
cd lift-app
bash scripts/server-setup.sh <домен>     # например lift.myrenthub.ru — A-запись домена должна указывать на сервер
```

Скрипт ставит свой Node.js, создаёт `.env` (порт с 3100, пароль команды), службу `lift-app`, автовыкладку
`lift-app-deploy.timer` (ветка main, откат при ошибке), бэкап в 03:50 (`~/backups/lift-app`), nginx и HTTPS.

```bash
sudo systemctl status lift-app              # работает ли
sudo journalctl -u lift-app -n 50           # журнал
tail -n 30 ~/backups/lift-app/deploy.log    # журнал автовыкладки
bash scripts/backup.sh                      # бэкап сейчас
```

## APK

GitHub → Actions → «Android APK» → Run workflow. Перед первым запуском:
Settings → Secrets and variables → Actions → Variables → `LIFT_URL` = `https://<домен>`.
Готовый APK — на странице запуска, раздел Artifacts. Это отладочная сборка для установки «вручную»;
для RuStore нужна подписанная release-сборка (ключ подписи храним в секретах GitHub) — следующий шаг.

Иконки и заставка Android — `apps/web/android/app/src/main/res/` (сгенерированы из логотипа), иконка 512×512 для
RuStore — `apps/web/public/icon-512.png`.

## Локально

```bash
npm install
echo -e "TEAM_PASSWORD=test\nPUBLIC_URL=http://localhost:5180" > .env
npm run dev            # приложение http://localhost:5180, команда http://localhost:5180/team
```

В git никогда: `.env`, `data/`, ключи подписи (`*.jks`, `*.keystore`).
