# Лифт — приложение для пилотов

## Что это
- Продукт владельца: помощь пилотам (клиентам) в стратегии развития бизнеса + сайт, боты в Telegram и MAX, SMM, автоматизация.
  «Лифт» — единое приложение для общения с пилотами: стратегия, задачи с дедлайнами, анкета (вместо Google Форм),
  инструменты (сайт, админка, боты), игра «этажи». Планы: RuStore, push-уведомления, реклама (VK Ads / Яндекс), SMM-раздел.
- Пилотов сейчас 4, через полгода ~100.
- Стек: apps/api — Express + SQLite (better-sqlite3), apps/web — React + Vite, APK — Capacitor (apps/web/android),
  сборка APK — GitHub Actions (.github/workflows/android.yml; из облачной сессии Android SDK скачать нельзя).
- Прототип экранов: https://claude.ai/artifact/7Ci9BR7A1nEL837v392VVW (там старое имя «Взлёт» и «эшелоны»; утверждено: «Лифт» и «этажи»).
- Оформление: чёрный + фиолетовый (#0B0A10, #7C3AED, #A78BFA, дедлайн #F5B14C), шрифты Unbounded + Manrope. Логотип — двери лифта со стрелкой вверх.

## Правила (как в соседних проектах владельца)
- На том же сервере (VM Yandex Cloud 51.250.82.145, пользователь mac-user) живут «Цех №4» (/home/mac-user/my-projects/wood-shop-max, служба wood-shop-max, порт 3000)
  и конструктор магазинов (/home/mac-user/my-projects/Shop_constructor, службы shop-constructor@*, порты с 3001, myrenthub.ru). Их не трогать.
- «Лифт» на сервере: /home/mac-user/my-projects/lift-app, служба lift-app, порт с 3100, nginx /etc/nginx/sites-available/lift-app.conf, бэкапы ~/backups/lift-app (03:50).
- В git никогда: .env, data/, ключи подписи APK.
- Перед каждым пушем: npm run build без ошибок.
- Визуальные правки: сначала скриншоты владельцу («было / станет»), пуш — после его «пушим».
- Доступа к серверу из облачной сессии нет: владелец выполняет команды сам — давать готовые к вставке.
- Владелец не программист: объяснять по-русски, простыми шагами.
- Персональные данные пилотов (152-ФЗ): согласие при входе (pilots.consent_at), политика /privacy (оператор — OPERATOR_NAME/EMAIL в .env, текст — шаблон, не проверен юристом).

## Сделано (v0.1)
- Вход пилота по ссылке-приглашению, вход команды по паролю; сессии — Bearer-токен (в базе только хеш).
- Пилот: главная (этаж, анкета, ближайшие задачи), стратегия (цель, этапы, заметка команды), задачи (отметка, баллы), инструменты, анкета 46 вопросов с автосохранением и загрузкой файлов.
- Команда (/team): таблица пилотов, приглашение, карточка пилота (профиль/цель, этапы, задачи, инструменты, ответы анкеты), архив.
- Серверные скрипты: scripts/server-setup.sh, deploy.sh, backup.sh.
- Согласование стратегии: цели (goals) и задачи со статусом proposed → accepted / declined (архив с причиной).
  Команда загружает стратегию JSON-файлом (панель → пилот → Стратегия → «Импорт стратегии»), пилот на экране
  «Стратегия на согласование» выбирает «Беру в работу» / «Не актуально», может вернуть из архива; команда — «Предложить снова».
  Логика — apps/api/src/model.ts (чистые функции, общие с демо-режимом). Стратегия «Цеха №4» — strategies/tseh4.json (13 целей, 52 задачи).
- Демо-APK (без сервера, пока не задан LIFT_URL): VITE_DEMO=1, apps/web/src/demo.ts — пилот «Цех №4» со стратегией на согласовании.

- Автопостинг (раздел «Посты» у пилота, вкладка «Посты» у команды): ВКонтакте (ключ пользователя-администратора сообщества,
  wall.post from_group=1, фото через photos.getWallUploadServer) и канал MAX (бот-админ канала, POST /messages?chat_id=,
  нужен NODE_EXTRA_CA_CERTS=deploy/certs/max-ca.pem). Планировщик раз в минуту, до 3 попыток (apps/api/src/posting.ts, publishers.ts).
  Ключи хранятся только на сервере (таблица channels), в API не отдаются. Instagram не подключаем (Meta — экстремистская в РФ, API недоступен).
